# MISSAV 4.0 UI 产品升级方案

> 状态：产品设计提案  
> 基线版本：3.4.0  
> 目标版本：4.0.0  
> 视觉方向：**原生 iOS、内容优先**  
> 技术基线：当前项目 TypeScript diagnostics 为 0

---

## 1. 执行摘要

MISSAV 3.x 已具备首页、浏览、搜索、资料库、推荐、详情、账号、系统播放器和 Home Tab，功能骨架完整；4.0 不应继续以“增加更多模块”为主，而应从可用工具升级为一套具有稳定心智模型、统一媒体语言、快速观看路径和可信状态反馈的原生 iOS 媒体产品。

4.0 的核心命题是：

1. **更快进入内容**：减少首页入口卡和重复栏目，优先呈现“继续观看、为你推荐、最近更新”。
2. **更快做出选择**：统一封面、标题、番号、时长、状态和推荐理由的信息顺序。
3. **更快开始播放**：详情页形成“主视觉 → 标题与元数据 → 单一主播放动作”的首屏闭环。
4. **更清楚地区分数据归属**：网站收藏、本机收藏、播放记录、浏览记录在标签、图标与说明上始终可辨。
5. **更稳定地跨入口运行**：独立入口与 Scripting Home Tab 使用同一内容语言，但各自遵循宿主导航和 toolbar 边界。

### 4.0 北极星体验

> 用户打开 MISSAV 后，应在 3 秒内理解当前可做什么，并在 2 次主要点击内开始播放已知内容；对未知内容，则能以一次筛选或搜索快速进入详情。

## 2. 项目事实与冻结边界

### 2.1 当前生产入口

| 入口 | 文件 | 产品角色 | UI 所有权 |
|---|---|---|---|
| 独立运行入口 | `index.tsx` → `page/index.tsx` | 完整四 Tab 媒体浏览器 | 项目拥有 NavigationStack、TabView、关闭、设置、最小化 |
| Scripting Home Tab | `home_screen_default_ui.tsx` | 快速入口与内容摘要 | 项目拥有唯一 NavigationStack 和内容；不得与宿主 trailing 菜单竞争 |
| 全屏系统播放器 | `native-player.tsx` | 沉浸播放 | AVPlayerView 拥有系统播放控制，项目不叠加自定义控制壳 |

### 2.2 产品原型

- 主类型：**单站在线媒体浏览器**。
- 辅助能力：本机资料库、网站账号收藏、个性化推荐、系统播放器。
- 内容策略：在线发现优先，本机数据用于续看、收藏和个性化。

### 2.3 业务冻结域

4.0 UI 升级默认不得改变：

- `client.ts` 的请求、页面解析、搜索、分页和视频 identity；
- `account.ts` 的站点隔离会话、Cookie/Keychain、网站收藏协议；
- `database.ts` / `storage.ts` 的 schema、主键、迁移、收藏与历史数据；
- `playback-source.ts`、`player.tsx`、`native-player.tsx` 的播放源筛选、刷新、系统播放器和画中画边界；
- `domain.ts` 的域名身份与切换语义；
- 推荐算法和本机数据“不上传”的隐私承诺。

如实施中必须触及以上文件，应作为独立业务变更评审，不得以 UI 重构名义混入。

### 2.4 明确禁止项

- 使用系统语义背景、原生控件、排版、留白和分隔线建立层级。
- 动效仅用于状态反馈和系统转场，避免与内容无关的持续装饰。
- 不以大面积渐变、半透明叠层、发光描边取代信息层级。
- 不在系统播放器上叠加自定义全屏控制 HUD。
- 不通过 offset、透明占位或固定魔数修复系统 toolbar。

## 3. 现状审计与机会

### 3.1 已有优势

- 四 Tab 结构清晰：`首页 / 浏览 / 资料库 / 搜索`。
- 已有共享媒体卡、媒体行和状态组件。
- 使用系统语义背景与文字色，浅深色自动适配。
- 主要异步页面已具备 latest-request-wins 或请求代次保护。
- 详情页明确区分本机收藏与网站收藏。
- 系统播放器边界正确，避免重复全屏和自定义控制冲突。
- 关键按钮普遍具备 44pt 命中区和辅助功能标签。
- TypeScript 基线无诊断错误。

### 3.2 P0：4.0 必须解决

1. **同一内容在不同页面的视觉语法不统一**  
   首页 `MediaTile`、浏览 `MediaGridCard`、搜索自定义大图结果、资料库 `VideoRow` 各自采用不同标题高度、封面高度和元数据顺序，用户需要反复重新识别。

2. **首页主入口与内容消费竞争**  
   独立首页顶部三张大型 Feature 卡占据首屏，其中“收藏”只打开第一条收藏，动作语义不符合用户预期。4.0 应让首页从“入口展示”转为“继续观看与内容流”。

3. **详情首屏操作层级过重**  
   播放、本机收藏、网站收藏连续三个全宽按钮，收藏状态说明再占一行；主播放动作虽明确，但次级动作对首屏干扰较大。

4. **资料库四段 segmented 在窄屏和大字下承压**  
   “网站收藏 / 本机收藏 / 播放 / 浏览”四项文本较长，且网站与本机归属需要更明确的非颜色线索。

5. **Home Tab 与独立入口体验割裂**  
   Home Tab 使用四个彩色入口块和自适应网格，独立入口使用大型横向 Feature；两套首页没有共享同一信息优先级与媒体组件。

6. **视觉色彩使用缺少语义分级**  
   搜索分类使用六种高饱和背景，首页 Feature 使用多种 tint；颜色同时承担品牌、分类和动作三种职责，容易造成“每块都重要”。

### 3.3 P1：显著提升产品品质

- 发现页首项 Hero 与后续网格关系较弱，翻页后仍显示 Hero 会放大普通首项。
- 搜索发现页“热门推荐 + 六分类”与浏览页栏目存在信息重复。
- 推荐理由只显示在普通状态行，没有解释推荐来自收藏、浏览还是播放。
- 刷新错误、局部错误和空状态虽完整，但页面间文案与布局密度仍有差异。
- 设置页“本次更新”占据较大篇幅，长期设置与版本营销信息混在同一主层级。
- 当前自动测试仅覆盖媒体源回归，UI 合同、存储连续性和分页状态缺少测试。

### 3.4 P2：增强项

- 加入最近搜索和清除最近搜索（本机、版本化存储）。
- 为播放记录提供明确“最近播放”时间或顺序说明（不承诺不存在的播放进度）。
- 为推荐提供“为什么推荐”说明面板与关闭单条推荐入口（仅在算法支持时实施）。
- iPad/宽屏采用更宽内容区与 3 列媒体网格，不改变信息结构。

## 4. 4.0 产品原则

### 原则 A：内容先于容器

封面、标题、番号、时长和状态是主角。容器只用于建立分组，不用大量卡片、底色和边框制造层级。

### 原则 B：一屏一个主任务

- 首页：继续与发现。
- 浏览：筛选与浏览。
- 搜索：表达意图并查看结果。
- 资料库：找回已保存或看过的内容。
- 详情：判断并开始播放。

### 原则 C：一个页面只保留一个主强调动作

详情页主强调仅为“播放”；收藏是次级动作。首页强调继续观看；空状态强调恢复路径。

### 原则 D：状态必须可解释

加载、刷新、离线、空、错误、部分成功、操作中、已收藏、不可用均有明确文字与非颜色图形线索。

### 原则 E：一致性优先于页面个性

同一视频在首页、浏览、搜索、推荐、资料库中复用有限的三种内容 archetype，而不是每页重新设计。

### 原则 F：原生但不默认

使用原生 Navigation、Tab、Menu、Picker、List、Button 和系统播放器；通过内容节奏、字体、媒体比例和语义 token 建立稳定的产品识别。

## 5. 信息架构

### 5.1 独立入口主导航

保持四 Tab，不新增无业务价值 Tab：

1. **首页**：继续观看、为你推荐、最近更新、热门。
2. **浏览**：栏目、筛选、排序、分页结果。
3. **资料库**：网站收藏、本机收藏、播放记录、浏览记录。
4. **搜索**：搜索输入、最近搜索、热门搜索入口、搜索结果。

设置继续作为根 toolbar 的低频入口，不进入 Tab。

### 5.2 Home Tab 信息架构

Home Tab 不复制完整四 Tab，而作为快速门户：

1. 顶部：简洁标题和一句状态摘要。
2. 继续观看：有记录时为首要内容；无记录时显示“开始探索”。
3. 快速入口：浏览、搜索、资料库、推荐，采用原生紧凑操作行或 2×2 轻量 tile，不使用大面积高饱和色块。
4. 当前热门：最多 4–6 项。
5. 最近更新：最多 4–6 项。
6. 设置：底部普通导航行。

Home Tab 与独立首页共享媒体组件与文案，但不共享带入口副作用的根运行文件。

### 5.3 页面关系

```text
独立入口
├── 首页
│   ├── 继续观看 → 详情 → 系统播放器
│   ├── 为你推荐 → 推荐列表 → 详情
│   └── 内容货架 → 详情
├── 浏览
│   ├── 栏目 / 筛选 / 排序
│   ├── 结果列表或网格
│   └── 详情
├── 资料库
│   ├── 网站收藏
│   ├── 本机收藏
│   ├── 播放记录
│   └── 浏览记录
├── 搜索
│   ├── 搜索建议 / 最近搜索
│   ├── 搜索结果
│   └── 详情
└── 设置
    ├── 站点
    ├── 网站账号
    ├── 数据与隐私
    └── 关于 / 更新日志
```

## 6. 原生界面设计系统

### 6.1 颜色角色

| Token | 用途 | 建议 |
|---|---|---|
| `color.background.canvas` | 页面环境 | `systemBackground` |
| `color.background.subtle` | 搜索框、筛选条、轻量状态 | `secondarySystemBackground` / `tertiarySystemFill` |
| `color.text.primary` | 标题与正文 | `label` |
| `color.text.secondary` | 元数据与说明 | `secondaryLabel` |
| `color.text.tertiary` | 弱提示与 accessory | `tertiaryLabel` |
| `color.brand.primary` | 主动作、选中、关键图标 | `systemPink` |
| `color.feedback.error` | 错误与危险 | `systemRed` |
| `color.feedback.success` | 已验证等成功状态 | `systemGreen`，必须伴随图标/文字 |

规则：

- 品牌粉只用于主动作、选中和少量关键状态，不涂满普通内容卡。
- 分类不再每项使用独立高饱和背景；用 SF Symbol、标题和简短说明区分。
- 深色模式不使用固定白字+彩底作为常态内容表达。
- 任何状态不能只用 tint 区分。

### 6.2 字体层级

| 角色 | 样式 | 使用位置 |
|---|---|---|
| Page Title | `largeTitle / bold` | Tab 根页系统导航标题 |
| Section Title | `title2 / bold` | 首页、搜索发现的大区块 |
| Content Title | `headline / semibold` | 列表行、详情辅助内容 |
| Hero Title | `title2 / bold` | 详情主标题、首要继续观看 |
| Metadata | `subheadline` 或 `caption` | 番号、时长、日期、推荐理由 |
| Supporting | `footnote` | 隐私、错误、状态说明 |

规则：同一张内容卡最多三个文字层级；番号与时长不与标题争夺强调。

### 6.3 间距与几何

- 页面水平 inset：手机 18pt；宽屏可提升到 24pt。
- 大 section 间距：28–32pt。
- 标题到内容：10–12pt。
- 同类内容项间距：12–16pt。
- 控件最小命中区：44×44pt。
- 全宽主按钮可见高度：52pt。
- 次级全宽行：48pt 以上。
- 媒体比例统一为 16:9。
- 图片圆角：列表 10pt、普通卡 14pt、Hero 18pt；不叠描边和阴影。

### 6.4 三种媒体组件

#### A. `MediaShelfTile`

用于首页横向货架：

- 184×104 封面；
- 两行标题；
- 一行“番号 · 时长”；
- 可选一行状态，存在状态时取代普通 metadata 的弱层级，不额外堆 badge。

#### B. `MediaListRow`

用于资料库、推荐、搜索结果：

- 112×63 封面；
- 最多三行标题；
- 番号与时长；
- 一行来源/推荐原因/历史状态；
- 右侧 chevron；
- 行间 Divider。

搜索结果默认使用此 row，以保持高信息密度；同时提供用户可切换、可持久化的 196pt“大封面”模式。两种模式必须共享结果 identity、分页和详情路径，大封面不得成为默认模式，也不得额外发起请求。

#### C. `MediaHero`

仅用于：

- 首页“继续观看”；
- 详情页首屏主视觉；
- 浏览第一页经过明确编辑逻辑选出的精选项。

普通分页首项不得自动升级为 Hero。Hero 文案尽量放在图片下方；如图片上必须覆盖，只允许底部单层高对比遮罩，且不承担所有信息。

### 6.5 状态组件

保留 `page / section / row` 三种密度，但统一内容顺序：

1. 图标或进度；
2. 状态标题；
3. 可执行解释；
4. 单一恢复动作。

局部刷新失败且有旧内容时，使用紧凑 inline status，不用大错误卡打断内容流。

### 6.6 动效与反馈

- 仅使用系统导航、Tab、Button、Menu、Picker 转场。
- 列表刷新采用系统 refreshable。
- 数字变化可用 `numericText`。
- 禁止持续性装饰动画。
- 异步动作立即进入 loading/disabled，结束后显示真实结果。
- 不承诺无法从播放器得到的观看进度百分比。

## 7. 核心页面方案

## 7.1 首页 4.0

### 页面目标

让用户优先继续观看，其次发现高相关内容，而不是先浏览功能入口。

### 建议结构

1. **继续观看 Hero**
   - 有历史：封面、标题、番号/清晰度或最近状态、主按钮“继续观看”。
   - 无历史：简洁空态“开始探索”，动作切到浏览 Tab。
2. **为你推荐**
   - 横向 `MediaShelfTile`，标题下显示简短推荐理由。
   - 提供“查看全部”进入推荐页。
3. **最近更新**
   - 横向货架，统一媒体卡。
4. **今日热门**
   - 横向货架；当远程请求失败但有缓存时仅显示 inline 状态。
5. **收藏快捷入口**
   - 不再打开第一条收藏。
   - 作为“查看全部收藏”的普通操作行，跳转资料库并预选本机收藏；若暂时无法跨 Tab 传 segment，则进入资料库默认收藏。

### 删除/降级

- 移除顶部三张同权重 286×166 Feature 轮播。
- “为你推荐”“收藏”从大视觉入口降级为内容货架或明确导航行。
- 不用三种 tint 表示三个同级产品动作。

### 成功指标

- 首屏至少看到一项真实内容或清晰恢复动作。
- 从首页到播放不超过 2 次主要点击。
- 收藏入口不再产生“为什么只打开第一条”的歧义。

## 7.2 浏览 4.0

### 页面目标

在保持筛选能力的同时，让用户知道当前正在浏览什么、筛选如何影响结果。

### 建议结构

1. 栏目选择：横向可滚动原生 chip；选中同时使用粗体、勾选或 symbol 变体，而非仅粉色。
2. 筛选与排序：两个完整 label 的 Menu，显示当前值。
3. 结果摘要：`栏目 · 筛选 · 排序 · 第 N 页`，可被 VoiceOver 连续理解。
4. 内容：
   - 第 1 页可选一个真正的精选 Hero；
   - 其他内容使用统一网格；
   - 第 2 页起不自动产生 Hero。
5. 分页：上一页、页码、下一页；切换后回到结果顶部。

### 建议交互

- 筛选变化立刻请求并将页码重置为 1。
- 加载时保留旧结果并显示局部进度，防止页面闪空。
- 错误时说明“正在显示上次结果”或“无可用结果”，两者不可混淆。

## 7.3 搜索 4.0

### 页面目标

搜索是明确意图通道，不再同时承担完整的第二套浏览首页。

### 零输入态

1. 搜索输入框；
2. 最近搜索（如实施 P2，本机保存，可单项删除/全部清除）；
3. 热门内容横向货架；
4. 4 个核心发现入口，使用轻量原生行/低饱和 tile；其余栏目引导到浏览页。

### 结果态

- 顶部显示查询词、结果数和页码。
- 默认使用 `MediaListRow`，快速扫描标题与番号。
- 提供“列表 / 大封面”显示开关；大封面模式延续 3.4 的 196pt 封面语言，但使用 4.0 的圆角、标题轴、metadata 和分隔线规范。
- 显示方式保存在本机，切换不重新请求网络、不改变结果 identity 或分页。
- “浏览分类”使用独立导航式文本动作，不与加载进度竞争；在窄屏和大字下与显示开关纵向排列。
- 空搜索不发请求，明确提示“请输入番号、女优或标题”。

## 7.4 资料库 4.0

### 页面目标

让用户快速理解内容归属并找回历史，而不是把四种来源压缩在一个过载 segmented control 中。

### 推荐方案：双层分类

第一层 segmented：

- **收藏**
- **历史**

第二层轻量 Picker/Menu：

- 收藏：网站收藏 / 本机收藏；
- 历史：播放记录 / 浏览记录。

优点：窄屏更稳定，心智模型更清楚，并减少四等分文本拥挤。

### 内容头部

- 标题 + 数据归属说明；
- 数量；
- 网站收藏显示账号状态 symbol 和“来自网站账号”；
- 本机数据显示设备 symbol 和“仅存于本机”。

### 列表与操作

- 统一 `MediaListRow`。
- “加载更多网站收藏”为标准全宽次级按钮。
- 清空历史放在页面底部 destructive Menu，并明确不会影响收藏。
- 空状态动作直接去浏览。

## 7.5 详情 4.0

### 页面目标

在首屏完成“识别内容 → 判断 → 播放”，同时让双收藏操作清楚但不抢占主任务。

### 建议结构

1. 16:9 主视觉；
2. 番号、标题、演员、日期/时长/制作方；
3. 单一全宽主播放按钮；
4. 一行次级操作：
   - 本机收藏 icon + 明确状态；
   - 网站收藏 icon + 明确状态；
   - 宽度不足或大字时自动纵向排列；
5. 收藏归属说明或错误说明；
6. 作品信息；
7. 标签；
8. 其他清晰度。

### 收藏交互

- 已收藏：`heart.fill + 已加入本机收藏` / `bookmark.fill + 已加入网站收藏`。
- 未收藏：outline symbol + 加入文案。
- 不可用：禁用 + 原因文字，不把失败伪装为未收藏。
- 网站账号失效时提供“前往设置登录”的恢复路径（若当前导航能力允许）。

### 播放交互

- 默认源只有一个主按钮。
- 其他清晰度使用原生行列表，不重复 bordered 按钮。
- 打开某个源时只锁定播放操作，不应无理由锁死无关信息阅读。
- 保持系统 AVPlayer、画中画与旋转边界不变。

## 7.6 推荐页 4.0

- 顶部使用简短隐私说明，不做大卡。
- 每一行显示可读推荐理由，并用 symbol 区分“来自收藏 / 来自播放 / 来自浏览”（仅在算法可提供类型时）。
- 推荐不足时说明如何产生推荐，并提供“前往浏览”。
- 不增加虚假的“智能 AI”营销表述。

## 7.7 设置 4.0

### 建议分区

1. **站点与连接**：域名、Safari 打开。
2. **网站账号**：账号状态、登录/验证、退出。
3. **播放与体验**：仅放真实可配置项；没有配置就不造空 Section。
4. **数据与隐私**：本机数据、网站同步边界，历史清理仍留在资料库。
5. **关于**：版本、更新日志、当前站点。

### 调整

- 将“本次更新”三条宣传内容移入更新日志；设置页只保留一行“4.0 更新摘要”或完全移除。
- 账号状态必须同时用 symbol 与文字表达，不能只靠绿色。
- 低频技术信息不占据设置主层级。

## 8. Presentation 与 Surface Owner

### 8.1 Presentation Owner Matrix

| Presentation | Navigation | Toolbar | Background | Dismiss / Exit | 状态源 |
|---|---|---|---|---|---|
| 独立四 Tab | `page/index.tsx` 唯一根 NavigationStack | 根壳层拥有关闭、设置、最小化 | 各 Tab 实际页面唯一 `PageBackground` | 页面 dismiss，入口完成 listener 清理后 exit | 根 revisions + 页面局部状态 |
| Home Tab | `home_screen_default_ui.tsx` 唯一 NavigationStack | 不占宿主 trailing；页面只用必要系统标题 | Home ScrollView 的单一 PageBackground | 无 Script.exit / minimize | Home Tab 本地 state + Home event |
| pushed detail | 所在 NavigationStack | 仅页面必要 navigation title | Detail 页面唯一背景 | 系统返回 | Detail request state |
| 设置 | 根 navigationDestination | 系统导航 | 原生 List 背景 | 系统返回/dismiss | 设置局部状态 + domain/account store |
| 全屏播放器 | `Navigation.present` 独立树 | AVPlayerView 系统控制 | 黑色媒体背景 | presentation 关闭后 finally dispose | AVPlayer owner |

### 8.2 Surface Owner Matrix

| Surface | Owner | 规则 |
|---|---|---|
| 页面环境 | `PageBackground` | 每个实际 presentation 一处，避免重复背景层 |
| Scroll/List | 页面 | 背景与系统环境一致，不出现顶部断层 |
| 内容封面 | `MediaArtwork` | 仅图片、占位、裁切与圆角 |
| 内容分组 | Section heading + spacing | 优先用留白与排版，不为每组增加卡片背景 |
| 输入/筛选 | 原生 TextField/Menu/Picker | 使用轻量系统 fill，完整命中区 |
| 主动作 | 原生 borderedProminent Button | 每页最多一个主强调 |
| 播放控制 | AVPlayerView | 禁止自定义覆盖系统 HUD |

## 9. 工程结构建议

当前 `index.tsx` 已较轻，4.0 不需要大规模重写业务层；应对 UI 层做最小、渐进式重组。

```text

├── index.tsx
├── design/
│   ├── tokens.ts
│   ├── typography.ts
│   └── primitives.tsx
├── page/
│   ├── app-shell.tsx
│   ├── home.tsx
│   ├── discover.tsx
│   ├── search.tsx
│   ├── library.tsx
│   ├── detail.tsx
│   ├── recommendations.tsx
│   ├── settings.tsx
│   ├── sections/
│   │   ├── home-continue-section.tsx
│   │   ├── media-shelf-section.tsx
│   │   └── detail-actions-section.tsx
│   └── components/
│       ├── media-artwork.tsx
│       ├── media-shelf-tile.tsx

```

实施原则：

- 不一次性创建全部目录；先抽取 4.0 垂直样板真正需要的组件。

- 页面不直接定义重复媒体卡。
- 不创建只转发 props 的空 bridge。
- 网络、账号、数据库和播放器不导入 UI 设计层。
- `home_screen_default_ui.tsx` 应复用无副作用组件，不导入运行入口。

## 10. 实施路线

### Wave 0：规格冻结与基线（0.5–1 天）

- 确认本方案的设计原则与业务冻结边界。
- 记录 3.4.0 diagnostics、运行结果、关键页面截图和已知问题。
- 建立业务冻结合同与功能等价矩阵。
- 冻结候选前不改网络、账号、数据库和播放协议。

**出口条件**：生产入口、冻结域、页面清单和回滚点明确。

### Wave 1：设计基础与共享内容组件（1–2 天）

- 将 `design.tsx` 收口为语义 token。
- 建立三种媒体 archetype：Shelf Tile、List Row、Hero。
- 统一 SectionHeading、ContentState、分页控件、轻量筛选 chip。
- 添加界面组件与视觉规范检查。

**出口条件**：共享组件在浅/深色和长标题下可用，无业务变更。

### Wave 2：垂直样板——首页 → 详情 → 播放（2–3 天）

- 重做独立首页首屏和内容货架。
- 重排详情首屏、主播放与双收藏。
- 验证系统播放器打开、关闭、画中画、旋转、历史写入。
- 覆盖 loading / partial / error / empty。

**出口条件**：该完整链路 diagnostics、运行与真机 P0 通过后才能扩页。

### Wave 3：浏览与搜索（2–3 天）

- 统一发现筛选与结果摘要。
- 限制 Hero 使用范围。
- 搜索结果迁移到统一 List Row；收敛零输入发现内容。
- 保留分页回顶和 latest-request-wins。

**出口条件**：搜索、分类、筛选、排序、分页无重复无旧结果串写。

### Wave 4：资料库、推荐、设置与 Home Tab（2–3 天）

- 资料库采用“收藏/历史 + 来源子筛选”。
- 推荐理由与隐私说明精修。
- 设置页降噪。
- Home Tab 对齐 4.0 内容优先语言，保留宿主边界。

**出口条件**：网站/本机数据归属明确，Home Tab 真机 toolbar 无冲突。

### Wave 5：收敛、测试与 RC（1–2 天）

- 搜索旧组件、重复样式、高饱和分类色块和遗留文案。
- 更新 `script.json`、设置版本、更新日志。
- 运行 diagnostics、项目 check、回归测试和真机矩阵。
- 创建 `4.0.0-rc.1` 候选并冻结范围。

**出口条件**：P0 全通过，无未决数据兼容风险，具备回滚点。

## 11. 验收标准

### 11.1 产品验收

- 首屏能明确回答“继续看什么 / 去哪里发现”。
- 首页到播放不超过 2 次主要点击。
- 搜索、浏览、资料库同类内容的标题与元数据顺序一致。
- 详情页仅一个主要强调动作。
- 网站收藏与本机收藏在任何页面均可通过文字和图标区分。
- 无内容、弱网、局部刷新失败不会出现白屏或无限等待。

### 11.2 视觉验收

- 页面背景、控件样式、内容层级和系统转场符合统一规范。
- Light/Dark 均使用系统语义色，无固定浅底/深底泄漏。
- 同类封面比例、圆角、标题行数和间距一致。
- 品牌粉仅用于主动作/选中/关键状态。
- 页面层级主要由排版、留白和分隔线构成。
- 最大常用动态字体下无标题溢出、按钮截断和 segmented 失效。

### 11.3 交互验收

- 所有图标按钮至少 44×44pt。
- Menu/Picker 完整可见区域可点击。
- 异步按钮防重复触发，并显示执行中状态。
- 分页、筛选、搜索切换采用 latest-request-wins。
- 切页后按产品语义回到结果顶部；“加载更多”保留当前位置。
- Home Tab 不占用宿主 trailing toolbar。
- 关闭、最小化、modal dismiss、播放器关闭语义不混用。

### 11.4 无障碍验收

- VoiceOver 可读出内容标题、番号/时长、状态和动作结果。
- selected/current/favourite/account/error 均有非颜色线索。
- 灰度、Increase Contrast、Reduce Transparency 下仍可区分状态。
- 最大常用 Dynamic Type、长中文/英文、窄屏无关键裁切。
- 按钮名称描述业务结果，不只读“心形”“书签”。

### 11.5 性能验收

- 首页在线与本机请求保持并行，不因 UI 重构重复请求。
- Lazy 容器继续用于长列表、横向货架和网格。
- 图片不增加多层覆盖、模糊、动态绘制。
- 页面切换不重建根 NavigationStack。
- 播放器关闭后 AVPlayer 必须 stop + dispose。

## 12. 自动化与真机门禁

### 12.1 自动化

每个 Wave 至少执行：

1. 项目 TypeScript diagnostics；
2. `scripting-ts project "MISSAV" --check`；
3. 现有媒体源回归；
4. 搜索以下禁止项：
   - 重复页面背景 owner
   - 页面级持续装饰动画
   - 自定义播放器控制层
   - 固定魔数 toolbar 修补
   - 非必要 `repeatForever`
5. 新增 UI 合同测试或源码检查：
   - 共享媒体组件被首页/搜索/资料库复用；
   - Home Tab 有显式 NavigationStack；
   - Home Tab 不导入 `index.tsx`；
   - Home Tab 不创建 `topBarTrailing`；
   - 播放器仍为单层 AVPlayerView；
   - 版本号在 metadata、设置和 changelog 一致。

### 12.2 真机 P0 矩阵

- iPhone 窄屏与常规屏；有条件时 iPad。
- Light / Dark。
- 最大常用 Dynamic Type。
- VoiceOver。
- Increase Contrast。
- Reduce Transparency。
- 灰度或用户常用色彩滤镜。
- 独立入口：Tab、设置、关闭、最小化、恢复。
- Home Tab：宿主菜单、滚动顶部、下拉刷新、无顶部模糊异常。
- 详情：双收藏状态、播放源失败、播放打开与关闭。
- 播放器：画中画、旋转、退出后无残余音频。
- 弱网：部分首页内容、详情刷新失败、分页失败、网站收藏失效。

自动检查通过只生成候选，不等于可发布；P0 真机未完成时为 No-Go。

## 13. 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| UI 重构误触解析或 identity | 收藏/历史断裂 | 冻结 client/storage/database；功能等价测试 |
| 首页重排增加重复请求 | 首屏变慢 | 保留 remote/local 并行与 TTL；请求计数审计 |
| 统一卡片后丢失页面特有状态 | 推荐理由或历史状态消失 | 组件提供单一可选 status slot，不复制新卡 |
| 资料库 IA 调整导致当前分类丢失 | 用户返回位置不稳定 | 使用稳定 string identity，明确默认值与切换规则 |
| Home Tab 复用根入口产生副作用 | Script.exit/toolbar 冲突 | 仅复用无副作用页面和组件，不导入 `index.tsx` |
| 过度追求大图降低信息密度 | 搜索效率下降 | Hero 严格限额；搜索与资料库使用列表行 |
| 界面被误做成彩色卡片堆叠 | 视觉噪音 | 分类色降级，品牌色集中，使用排版与留白建立层级 |
| 真机与 Preview 不一致 | 错误修复系统 chrome | 真实 Home Tab 和播放器作为最终证据 |

## 14. 发布判断与候选管理

建议候选 identity：`MISSAV 4.0.0-rc.1`。

### Go

- diagnostics 与自动回归通过；
- 所有 P0 真机项通过；
- 无新增业务/数据兼容问题；
- 版本、设置、CHANGELOG 一致；
- 回滚到 3.4.0 不损坏用户数据。

### Conditional Go

仅允许非阻塞 P2 视觉细节或明确 N/A 项，且有负责人和后续版本。

### No-Go

- 任一 P0 未执行或失败；
- 出现收藏、历史、账号会话或播放 identity 回归；
- Home Tab toolbar 与宿主冲突；
- 播放器退出仍有音频/资源未释放；
- 引入与内容无关的持续装饰效果或重复背景层；
- 修复后仍使用旧候选截图或测试证据。

## 15. 建议成功指标

在当前项目未内建分析系统的前提下，先以可观察任务指标验收，不要求上传用户行为：

- 首页首个有效内容出现时间；
- 首页到播放的操作步数；
- 搜索提交到结果可见时间；
- 筛选/翻页后的旧结果串写次数（目标 0）；
- 播放源打开成功率；
- 详情收藏状态不可判定率；
- 真机 P0 通过率；
- UI 组件重复实现数量；
- diagnostics 与回归失败数。

隐私原则：不为 4.0 指标新增远程行为上传；如需统计，优先使用开发期本机日志与人工任务测试。

## 16. 最终建议

4.0 应被定义为一次**信息架构与内容语言升级**，而不是一次换皮：

- 保留成熟的四 Tab、账号、数据和播放器能力；
- 首页从“功能入口轮播”转向“继续观看与推荐内容流”；
- 搜索、浏览、资料库统一媒体组件与元数据语法；
- 详情强化单一播放主路径，收藏退居清晰的次级动作；
- Home Tab 与独立入口共享设计系统但严格隔离宿主行为；
- 全程坚持系统语义色、清晰内容层级和原生交互。

这条路线既能形成明显的 4.0 视觉与体验跃迁，也能最大限度保护当前 3.4.0 已稳定的解析、账号、收藏、历史和播放能力。
